## 产品概述

在现有数据导出页面（/export.html）新增"增量对比"功能，解决群聊数据持续爬取后导出更新的痛点。用户已有上月导出的数据包上传到 NotebookLM，本月再次导出后，通过将两个数据包导入页面进行对比，自动得出不重合的新增消息，生成"补充包"供继续上传。

## 核心功能

- 在 /export.html 页面新增"增量对比" Tab，与现有"成员发言导出""每日群聊日报"并列
- 支持导入两个导出数据包文件（旧包 + 新包），自动识别 JSON / CSV 格式
- 用 (sender_name + text + 出现顺序序号) 组合键做去重对比，求出新包有但旧包没有的新增消息
- 对比结果展示：旧包条数 / 新包条数 / 新增条数 / 重复条数，以及两包首条发言者供用户肉眼核对
- 新增消息可按 JSON 或 CSV 格式导出为补充包，格式与现有 --export 完全一致，可直接上传 NotebookLM
- 纯前端完成，不新增后端 API，不修改导出格式，不改爬虫逻辑

## Tech Stack

- 前端：原生 HTML + JavaScript + CSS（与项目现有 web/ 目录技术栈完全一致，零新增依赖）
- 后端：无改动（server.py 不新增 API）
- 文件解析：前端 FileReader + JSON.parse / 轻量 CSV 解析

## Implementation Approach

### 核心策略

纯前端集合差集计算。用户通过文件选择控件导入旧包和新包，JS 解析后构造组合键集合求差集，结果通过 Blob 直接下载。不涉及后端 API、不涉及数据库查询、不涉及文件上传存储。

### 组合键去重算法

key = `sender_name \u0001 text \u0001 seq`，其中 seq 是该 (sender_name, text) 在同文件内第几次出现（从 0 递增）。

- 旧包构建 `Map<baseKey, count>`，baseKey = `sender_name \u0001 text`，value 为该组合出现次数
- 新包遍历每条，维护 `Map<baseKey, cursor>` 游标，若 cursor < 旧包 count 则视为重复（cursor++），否则为新增
- 正确处理"同一文本发了 N 次，旧包 M 次、新包 K 次（K>=M），新增 K-M 条"的场景

### 格式兼容

- JSON：`[{sender_name, text}, ...]` 纯数组，直接 JSON.parse
- CSV：表头 `sender_name,text`，UTF-8-SIG（可能带 BOM），用轻量状态机解析（处理引号内换行/逗号）
- 旧包与新包格式可不同（如旧 CSV + 新 JSON 也能对比）
- 输出补充包格式由用户选择（JSON 或 CSV），与现有 --export 格式一致

### 同群+同成员校验

当前导出文件不含 gid/sender_id 元信息，采用宽松校验：UI 展示两包首条 sender_name 供用户自行核对，不强制阻断。若两包首条 sender_name 不同，给出醒目提示。

### 性能

- 纯前端 JS，单文件通常几百到几千条，Map 查找 O(1)，整体 O(n+m)，无性能瓶颈
- 大文件（万条级）也仅需秒级，无需 Web Worker

## Implementation Notes

- 复用现有 `escapeHtml`、`metaItem`、`setStatus`、`showError`、`clearResult` 工具函数，不重复造轮子
- 复用现有 `#result-area`、`#preview-table`、`.form-card`、`.primary-btn` 等 DOM/CSS 结构
- Tab 切换逻辑扩展：现有 `switchTab` 硬编码 member/daily，需改为通用模式支持 diff
- 文件下载用 Blob + `a.click()`，与现有 download 逻辑风格一致但不走后端 token
- CSV 解析需处理 BOM 前缀（`\uFEFF`）、引号转义、字段内换行
- CSV 输出需加 BOM 前缀保证 Excel 中文不乱码（与后端 utf-8-sig 一致）
- 不修改 weibo_im/export.py 导出格式（用户明确要求不改）
- 不修改 crawl.py CLI、不修改 server.py（零后端改动）

## Architecture Design

### 数据流

```
用户选择旧包文件 → FileReader 读取文本 → 检测格式(JSON/CSV) → 解析为 [{sender_name, text}] 数组
用户选择新包文件 → 同上解析
组合键去重对比 → 新包减旧包 → 新增消息数组
用户选择输出格式(JSON/CSV) → Blob 序列化 → a.click() 下载补充包
```

### 模块划分

- **HTML 结构**：新增 Tab 按钮 + diff 面板（两个文件槽 + 格式选择 + 对比按钮 + 结果区复用）
- **JS 逻辑**：新增 `parseFile()`（格式检测+解析）、`computeDiff()`（组合键差集）、`renderDiffResult()`（结果渲染）、`downloadDelta()`（Blob 下载）
- **CSS 样式**：新增文件上传槽、拖拽提示等少量样式

## 设计风格

延续现有 /export.html 页面的简洁卡片式风格，配色体系不变（主色 #1a73e8、背景 #f5f5f5、卡片白底圆角）。增量对比 Tab 与现有两个 Tab 视觉完全一致，无突兀感。

## 页面规划

在现有 /export.html 页面 Tab 栏新增第三个 Tab"增量对比"，对应面板内含：

### 增量对比面板（tab-diff）

- **文件上传区**：左右并排两个文件槽，左侧"旧数据包（上次导出）"右侧"新数据包（本次导出）"，各含文件选择按钮 + 文件名显示 + 条数显示
- **格式选择行**：补充包输出格式 JSON / CSV 单选（默认 JSON）
- **对比按钮**：主按钮"开始对比"
- **结果展示区**：复用现有 result-area，展示旧包条数/新包条数/新增条数/重复条数 + 两包首条发言者核对信息 + 下载补充包按钮 + 前 50 条新增消息预览表格（发言者/正文两列，复用 #preview-table）
