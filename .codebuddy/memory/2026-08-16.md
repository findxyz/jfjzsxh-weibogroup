## 增量对比导出功能（web/export.*）

用户痛点：群聊持续爬取，上月导出的数据已上传 NotebookLM，本月再导出后无法重新上传全量包，需要"补充包"。

用户提出方案：做页面导入两个数据包（旧+新），对比得出不重合的新增数据作为增量补充包。

### 用户确认的关键决策
- 去重键：不改导出格式，用 `(sender_name + text + 出现顺序序号)` 组合键
- 对比范围：仅限同一群+同一成员（UI 展示前 10 条 sender_name 供核对，不强制阻断）
- 补充包格式：与现有 --export 一致（JSON/CSV）
- 页面：在 /export.html 加第 3 个 Tab"增量对比"

### 实现（纯前端，零后端改动）
- `web/export.html`：新增 diff Tab + 面板（两个文件槽 + 格式选择 + 对比按钮 + 结果区复用）
- `web/export.js`：
  - `parseCsv()` 轻量 CSV 解析（BOM、引号、字段内换行/逗号、引号内 \r\n 归一化为 \n）
  - `computeDelta()` 组合键差集：旧包建 `Map<baseKey, count>`，新包按序消费配额，超出为新增
  - `renderDiffResult()` 展示旧/新/新增/重复条数 + 前 10 条 sender_name 核对
  - `downloadDelta()` Blob 下载，文件名 `delta_YYYYMMDD_HHMM.{json|csv}`
  - 下载按钮行为按 activeTab 分流：diff 走前端 Blob，member/daily 走后端 token
- `web/export.css`：新增 .diff-files-row / .diff-file-slot / .diff-file-btn 等样式

### 测试
12 个场景全过：基本差集、同文本多条、旧比新多、完全相同、CSV 解析（BOM/表头/引号/字段内换行/引号转义）、CSV 往返、空旧包、不同 sender 同 text。

### 未改动
- `weibo_im/export.py`（导出格式不变）
- `crawl.py`（无新 CLI）
- `server.py`（无新 API，对比纯前端）

## 同步失败提示 + Cookie 一键续期（web 同步按钮增强）

用户痛点：页面顶部「同步」按钮点击后若失败（典型 cookie 过期），仅显示一行灰色小字、无原因、无引导。

### 用户确认决策
- 提示形式：醒目橙红横幅 + 可折叠分步指引。
- 续期触发：网页端一键触发（服务端 headless 截图二维码，前端展示扫码）。

### 实现
- `server.py`：新增续期长任务机制 `_renew_state`/`_renew_worker`/`_start_renew`/`_renew_status`/`_stop_renew`（与同步同构，二者互斥）。
  - 新增路由：`POST /api/renew`（启动，409=已在跑/同步中）、`GET /api/renew/status`（轮询，含 qrcode_url+stage）、`POST /api/renew/stop`。
  - 新增 `GET /qr/<file>` 静态路由（仅允许项目根 `qrcode.png`，防穿越），与 `crawl.py` 的 `QRCODE_PATH` 一致。
  - 续期命令强制 `[sys.executable, "crawl.py", "--renew-cookie", "--headless"]`（服务器无桌面必须无头）。
  - stage 取值：idle / waiting_scan / scanning / done / failed；前端按此渲染。
- `web/index.html`：在 `#topbar` 后新增 `#error-banner` 与 `#renew-panel`（可折叠步骤卡：一键续期按钮、二维码 img、状态、手动命令复制块、日志 details）。
- `web/style.css`：新增横幅/步骤卡/二维码/命令复制块样式（橙红警示、浅色卡片、圆角阴影）。
- `web/app.js`：改造 `pollSync` 失败分支 → `showSyncError(output)` 按日志关键字（Cookie 已过期/未设置 → cookie 类）渲染横幅并自动展开步骤卡；新增一键续期流程 `startRenew`/`pollRenew`/`stopRenew`，展示二维码、同步互斥、成功后提示并可重新同步。

### 验证
- code-explorer 子代理核对：未破坏同步/导出/媒体功能；HTML 17 个 id 与 JS 引用完全对应；stage 前后端一致。

### 注意
- 续期成功/失败均依赖 `crawl.py --renew-cookie --headless` 输出日志关键字推断 stage；Playwright 未安装时退出码非 0，前端提示 `uv run playwright install chromium`。

## 续期交互简化（用户二次反馈）

用户嫌上一版（横幅+折叠步骤卡+手动命令）太复杂，要求：
1. 出现 cookie 过期时**直接弹窗**提示一键续期，不要其他方法/手动命令。
2. 二维码截图**直接放大**显示；扫码后关闭截图显示「正在处理」；处理成功**关闭所有提示**。

### 改动
- `web/index.html`：删除 `#error-banner` 与 `#renew-panel`（步骤卡），改为单个 `#renew-modal` 居中弹窗（含初始态「一键续期并登录」按钮 + 扫码态放大二维码 `#renew-qr-img` + 状态 + 取消按钮）。
- `web/app.js`：
  - `showSyncError` 仅对 cookie 类失败调用 `showRenewModal()` 自动弹出；其他失败保持状态栏小字（不再弹窗）。
  - `startRenew` 点击后切到扫码态展示放大二维码；`pollRenew` 在 `scanning/done` 时收起二维码显示处理中；`done` 成功后静默刷新并 `closeRenewModal()` 关闭整个弹窗。
  - 移除所有手动命令复制、步骤卡、徽章逻辑。
- `web/style.css`：删除旧横幅/步骤卡样式，新增 `.renew-modal` 居中弹窗 + `.rm-qr-img`（260×260 放大）+ 弹出动画。

### 当前续期交互最终形态
同步失败(cookie) → 自动弹出续期弹窗 → 点「一键续期并登录」→ 放大二维码 → 微博 APP 扫码 → 收起二维码显示「正在处理」→ 成功 → 自动关闭弹窗并刷新。
